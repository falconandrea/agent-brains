## Findings and limits

The real-provider/fullscreen execution gap is narrowed to an observed complete
pipeline ending needs_human. Authentication worked for these calls; retries,
rate limits, failures, cancel/resume, plan revision, fix loops, other platforms
and broader model/task behavior were not exercised. No reliability rate follows
from this single valid plan. RV4 test-first evidence remains pending: the verifier
was pre-existing and no failing pre-implementation command was captured.

The plan/review conflict is a bounded planner-contract finding: the planner
introduced an acceptance criterion without distinguishing implementation files
from required workflow artifacts; the reviewer followed that literal criterion.
This is not a provider or TUI crash. Keep it as an RV2 evaluation case alongside
the historical missing-TITLE outputs, without relaxing deterministic validation
or deleting document/resume artifacts.
