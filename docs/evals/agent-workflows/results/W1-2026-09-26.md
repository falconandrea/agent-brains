# W1 — Solution capture pilot

## Scope

W1 tested the explicit-only `solution-capture` prototype against two verified
problems in a Laravel fixture project. A trivial documentation edit exercised
the rejection path. A fresh read-only session then tested retrieval from symptom
terms alone.

- Fixture: `ga-analytics` at commit
  `d0151a0e3d34b1a059081750b218116db805d0cf`
- Runtime: OpenCode CLI `1.18.32`, `zai-coding-plan/glm-5.3`, Laravel Sail
- Trial bound: two sessions and two real problems

## Acceptance results

| Check | Result | Evidence |
| --- | --- | --- |
| Verified capture | Pass | The queue hand-off failure was reproduced red, fixed, verified green, proposed at the gate, corrected, approved, and written once. |
| Retrospective capture | Pass | The SQLite date-cast upsert regression was confirmed against current code and its focused test before approval. |
| Fast path | Pass | An English-only editorial cleanup failed qualification and produced no proposal or artifact. |
| Approval boundary | Pass | Each qualifying case stopped at the proposal gate and wrote only after explicit approval. |
| Progressive retrieval | Pass | A fresh session found each solution from the index and targeted terms without opening the unrelated solution. |
| Index discipline | Pass | Each solution produced one detailed document and exactly one resolving `lessons.md` entry. |

The focused regression checks and the related feature suites passed in the
fixture during the pilot. Human review corrected unsupported or overly broad
claims before either solution document was finalized.

## Findings

- Explicit invocation kept capture a deliberate judgement rather than an
  automatic documentation side effect.
- The three-of-five qualification threshold admitted both non-obvious,
  reusable diagnoses and rejected the trivial edit.
- A one-line index was sufficient for targeted retrieval; the detailed
  documents did not need to be preloaded.
- The proposal gate prevented unsupported facts and unapproved writes from
  entering project memory.

## Limits

- The pilot covered one Laravel project, two problems, and one model/provider
  configuration; it does not establish cross-stack performance.
- The 180-day review interval is a maintenance policy, not a duration validated
  by this pilot.
- Session transcripts and machine-specific configuration were deliberately
  excluded from the public repository. This report retains the durable
  behavioral evidence without local paths, session identifiers, or fixture
  source transcripts.

## Decision

W1 passed its behavioral acceptance checks and was promoted:

- `solution-capture` moved into the canonical skill store as explicit-only;
- the skill is distributed through the common and full profiles;
- the solution template is scaffolded idempotently;
- `feature` and `diagnosing-bugs` perform targeted solution retrieval; and
- `lessons-gardener` audits solution links, duplicates, and review candidates.

The normative behavior remains in the
[W1 design](../W1-solution-capture-design.md). Executable coverage lives in
`tests/solution-capture-skill.test.ts`.
