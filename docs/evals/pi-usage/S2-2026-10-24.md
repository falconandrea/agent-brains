## Question

What does a real child-session exploration call cost and take, in the exact
shape the `/feature` workflow issues it — and can we record provider/model,
tokens, cache usage, SDK-exposed cost and elapsed time per call and per run,
surviving run logs and resume, so that S1 (context deduplication) and any
future S3 worker can be compared on TOTAL cost and latency rather than parent
token counts alone?

## Instrumentation (what changed)

One Pi-free module owns the shapes: `src/usage.ts`. Every layer folds usage
through it, so workflow totals, resume replay and `/flow status` count
identically.

| Layer | Change |
|---|---|
| `src/usage.ts` | Single owner of `CallUsageDetail`, `UsageTotals`, `UsageCoverage`, the fold, replay fold, defensive SDK-message reader, model labeling and copies. Token/cache totals are **optional**; absent means never reported. |
| `src/pi/pi-agent-runner.ts` | Captures the full SDK `Usage` of every assistant message in **every** `agent_end` batch of one `session.prompt()` (retries/compaction emit more than one), de-duplicating repeated assistant message objects by identity. Resolved `provider` and the full `model` id are stored separately. `elapsedMs` wraps `session.prompt` in `finally`, so a failed or tokenless call still reports wall-clock. The exported `buildResourceLoader()` is the production loader the audit reuses. The `onEvent` trace gains a whitelisted `args` (`path`/`pattern` only) for read/reread counting — never rendered, never persisted. **P1 fix (2026-10-26, uncommitted):** `buildResourceLoader()` sets `noExtensions: true` (child constraint) and the new exported `buildLoadedResourceLoader()` reloads the loader before `createAgentSession()` — an unreloaded loader injects zero context/skills, which is what every pre-fix child session ran with. |
| `src/workflows/feature.ts` | `recordUsage` folds the whole per-call detail into per-role totals: token/cache sums, `cost`/`elapsedMs` that stay `undefined` until some call reports them, distinct models, call count and coverage. `agent.completed` carries the per-call detail uncoerced. |
| `src/ports.ts` | `agent.completed.usage` and `workflow.outcome.usage` are the S2 shapes; `workflow.outcome` gains `elapsedMs` = wall-clock of the launch segment. |
| `src/run-launcher.ts` | Persists the full totals (the pre-S2 "cost dropped" behavior is gone). `renderUsage` prints `?` for an unreported field instead of an invented zero, never prints a cache segment nobody reported, and appends `partial` when a total covers fewer calls than were folded — judged BOTH per role and on the cross-role sums, so a `total`/`sdk cost`/`cache`/`elapsed` value summed from only some roles is marked incomplete. `fmtDuration` rounds to whole seconds **before** splitting minutes, so `119_600 ms` renders `2m00s`, not `1m60s`; `fmtCost` keeps a real sub-cent cost visibly nonzero instead of printing `$0.0000`. |
| `src/workflows/resume.ts` | Replay folds `agent.completed` events with the same helper: the resumed run seeds from the log and adds only NEW calls. |
| `extensions/pi-brain.ts` | `/flow status` folds live usage with the shared helper; `/flow log` renders per-call and per-run values without inventing zeros and shows cache only when reported. |

### Missing vs zero, and coverage

This is the contract the whole change rests on:

- A field that is **absent** was never reported (unavailable).
- A present **`0`** was reported as zero.
- Nothing coerces `undefined` to `0` at any boundary. A cost-only payload stays
  `{ cost }`; it does not become `input: 0, output: 0, cacheRead: 0`.
- A present total is a sum over the calls that reported that field.
  `UsageTotals.coverage[field]` records how many did; when it is lower than
  `calls`, the aggregate is **partial** and the renderers say so. The same test
  applies to the cross-role sums: if one role reported cost and another folded
  calls without one, the rendered total cost covers fewer calls than were made
  and is marked `partial`.
- Totals replayed from logs that predate coverage have `coverage` absent:
  their completeness is unknown and is never guessed as complete or partial.

`cost` is the cost **exposed by the Pi SDK**, computed from the provider's
published per-million rates. It is labeled `sdk cost` everywhere. It is not an
invoice, not billing and not an estimated saving; subscription plans can
differ and pi-brain never sees the real invoice.

Pi 0.84.2's `Usage` also exposes `cacheWrite1h` (a breakdown of `cacheWrite`),
`reasoning` (documented as a subset of `output`) and `totalTokens` (the token
sum), plus a per-component `cost` object. None of them is stored as a separate
metric: that would double-count or imply a price Pi does not report. The
instrumentation records exactly `input`, `output`, `cacheRead`, `cacheWrite`,
`cost.total` and its own `elapsedMs`.

### Retries, compaction and model ids

`agent_end` is the end of one agent-loop invocation, not necessarily the end of
one `session.prompt()`: automatic retries and compaction recovery call
`agent.continue()`, and each invocation emits its own `agent_end` with the
messages of that invocation. Replacing the captured usage per event would keep
only the last execution. The runner therefore keeps every batch and folds them
with `usageFromAgentEnds()`, which ignores an assistant message object it has
already seen (identity de-duplication) while adding distinct executions.

The SDK's `provider` and `model` are stored as separate fields. An OpenRouter
model id can itself contain `/` (`anthropic/claude-sonnet-4`); it is never
split. A call whose assistant messages disagree on provider/model stays
unlabeled rather than being attributed to one of them.

The defensive reader also treats `usage: null` as "nothing reported" instead
of throwing, because `typeof null === "object"` is exactly the trap untyped
SDK payloads set.

## Environment and method (corrected isolation)

Same isolation rules as U16, with the review's isolation defect fixed:

- Fresh temporary `HOME` and Pi agent directory; the run writes nothing into
  this repository or any consumer project (the evidence files under `runs/`
  were copied here deliberately after each run).
- The model catalog is an **independent copy** of `models-store.json`, not a
  symlink. The SDK store is writable, and a catalog update could otherwise
  reach the personal file through the link. `run-baseline.mjs` refuses a
  symlinked catalog with exit 2 before any SDK load (evidence:
  `runs/2026-10-24-symlink-guard.txt`).
- Credentials come from ambient environment keys (e.g. `OPENROUTER_API_KEY`,
  `ZAI_API_KEY`). No credential file was copied, symlinked or recorded; the
  personal `auth.json` (OAuth, other providers) was never read. The SDK wrote
  only a 2-byte `auth.json` (`{}`) inside the disposable directory.
- Project: this repository at the instrumented working tree. The S1 rerun uses
  the same tasks and grading keys on the post-S1 tree — the protocol, not the
  tree, is the constant.
- Runner: the production `PiAgentRunner` — the same session construction,
  resource loader and tool allowlist the `/feature` roles use. Read-only role,
  `read/grep/find/ls`, no skills. The three repo tasks inject no context files:
  raw multi-file exploration by direct reads. *(Post-P1 note (2026-10-26): at
  recording time the runner passed an UNRELOADED loader to
  `createAgentSession()`, so these sessions received no injected context or
  skills at all — the usage accounting is unaffected, but "the child receives
  the fixture AGENTS.md" was never true for these calls.)*
- Primary model: `zai/glm-5.2` (the machine's configured default), pricing
  1.4/4.4/0.26/0 USD per million (input/output/cacheRead/cacheWrite). The
  definitive 2026-10-25 run used this model. Earlier validation runs used
  `openrouter/mistralai/mistral-nemo` while zai was quota-blocked (pricing
  0.019/0.03/0/0).

## S1 deduplication and post-S1 comparison (2026-10-25)

S1 is implemented on top of the S2 commit `fb66860` and deliberately left
**uncommitted for review**. Its measured tree is identified in
[`runs/2026-10-25-post-s1-provenance.txt`](runs/2026-10-25-post-s1-provenance.txt)
(tree fingerprint `2a72af34…`; tracked diff sha256 `1605738e…` plus the two
untracked files listed in the manifest).

### What changed

- **`src/context-dedup.ts` (new, Pi-free).** `canonicalAgentsPath(cwd, path)`
  resolves relative paths against `cwd` and canonicalizes the raw path with
  `realpathSync.native`, so `AGENTS.md`, `./AGENTS.md`, `sub/../AGENTS.md`, an
  absolute alias and a symlink alias collapse to one key with filesystem
  semantics (a symlink is resolved before `..`). For a not-yet-existing tail it
  resolves the longest existing prefix and appends the rest, so injected
  virtual files still get a stable absolute key.
  `dedupeAgentsFiles(cwd, discovered, injected)` merges
  both sources, preserves first-seen order (discoveries first, injection-only
  files appended in request order) and returns fresh objects.
- **Production wiring.** `buildResourceLoader()` in
  `src/pi/pi-agent-runner.ts` now passes `base.agentsFiles` plus
  `request.contextFiles` through `dedupeAgentsFiles()` inside
  `agentsFilesOverride`. The audit and the real calls therefore exercise the
  same production loader builder.
- **Deterministic precedence for conflicting content at one canonical path:**
  1. an explicit `request.contextFiles` entry wins over a discovered entry;
  2. among explicit entries, the first in request order wins;
  3. among discovered entries, the first discovery wins.
  Identical duplicates collapse silently. A real content conflict is never
  silent: `buildResourceLoader()` writes one stderr line per conflict naming
  the canonical path, the winner/loser origin and both truncated sha256 hashes.
  The child prompt still receives exactly one entry.
- **Scope held.** No skill filtering change (`skillsOverride` is untouched), no
  S3 bulk-reader, no new plugin, no profile or reviewer change. Injected-only
  paths keep the path form they were supplied with; only the dedup key is
  canonical.
- **Review fixes (2026-10-26).** Two edge cases found in review were fixed
  before commit:
  - *First-injection precedence.* An injected entry whose bytes matched the
    discovery used to return before claiming the slot, so a later injection
    with different content could override it. An identical injected duplicate
    now transfers the slot to `injected`, so the first injection wins whether
    or not its bytes match the discovery. Regression: `an identical first
    injection claims precedence over a later injection`.
  - *Symlink followed by `..`.* `path.resolve()` — and the JS
    `realpathSync` — normalize `..` lexically. With `alias -> nested/sub`,
    `alias/../AGENTS.md` names `nested/AGENTS.md` on the filesystem, but the
    lexical form looked like the root `AGENTS.md` and collapsed two distinct
    instruction files. `canonicalAgentsPath()` now resolves the raw path with
    `realpathSync.native`; when the tail does not exist yet, it resolves the
    longest existing prefix the same way and appends the rest. Regressions
    cover the relative and absolute forms.

**Reading it honestly:**

- **No metric separates from noise at n=4.** Cost deltas mix signs
  (−$0.0006, +$0.0008, +$0.0001, +$0.0004; 3 of 4 positive, sign-test
  p=0.625); output leans higher in B (3 of 4) exactly as weakly. The
  largest single driver is A's pair-1 input outlier (895) — the first call
  of the run, consistent with a cold provider cache (see below).
- The dedup's static effect is ~286 rendered bytes ≈ ~70 tokens per
  re-sent round (heuristic). The input-side means move in the expected
  direction (A 3,177 vs B 3,141, −36) but the within-branch spreads
  (A 3,123–3,199; B 3,073–3,211) are the same size as the effect, so no
  saving is attributable. Priced at cacheRead rates the theoretical effect
  is ~$0.00004/call — roughly 40 times smaller than the observed cost
  range width (~$0.00157, from $0.00198 to $0.00355). This heuristic is not a
  measured saving or a statistical detection limit.
- Latency: B's mean is lower (7.5s vs 9.0s, 3 of 4 paired deltas negative)
  with heavily overlapping ranges — noise, no claim.
- Behavior was symmetric this time: 7 of 8 calls read only `src/limits.ts`
  (one B call also read `AGENTS.md`); answers similar length in both
  branches. Contrast with the invalid run, where B "consistently" explored
  more and cost more — with both prompts identical that pattern was
  not attributable to S1. Identical prompts do not establish whether the
  variation came from randomness, cache/order effects or another factor.

### Cache and order effects (recorded, not inferred)

The coldest call is again the run's very first (pair 1 slot 1, A): highest
input (895) and lowest cacheRead (2,304). Every later call in both branches
sits in a tight cacheRead band (2,688–3,008) with no monotonic trend, so
provider-side warm-up benefited at most that first call — assigned to A by
the alternating order, i.e. against the branch a saving would favor. Each
call re-sends the conversation per tool round; with 1 read per call the
round structure was near-constant, which is why the corrected run's
input-side totals are far tighter than the invalid run's (which varied in
exploration). Timestamps per call are in the raw JSON.

### Answer quality

**8/8 correct** against the protocol keys: retry limit **7**, marker
**`FIXTURE-AGENTS-MARKER`**, `MAX_BATCH_SIZE = 42` in `src/limits.ts`.
Deterministic keyword checks pass 4/4 items on every call; every answer was
read in full. Notably, most correct marker citations now come from the
injected context (only 1 of 8 calls read `AGENTS.md` from disk), unlike the
pre-fix protocol runs where the marker was necessarily learned by direct
read — the injection actually works now.

### What this closes

With the manipulation proven per call (loader audit AND system-prompt gates
on the same instance the session uses), the corrected experiment found
**no benefit detected in these four pairs**. We chose not to expand this
bounded experiment: the heuristic saving is small relative to the observed
variation. This does not prove that a benefit is absent or undetectable;
additional pairs could reduce uncertainty and reveal a small effect. S1
stands on correctness and
deterministic precedence (now verified end-to-end into the real session
prompt, exactly one copy), **not** on measured savings; **S3 gains no cost
justification from S1** and would need its own total-cost/latency/quality
comparison. The P1 fix itself is the load-bearing outcome for production:
child sessions now actually receive their routed context and router-selected
skills (extensions still excluded), which every pre-fix run silently lacked.

## Limits

- **The definitive baseline is measured; the older 3-task table is not it.**
  The 2026-10-25 4-task run above replaces the pre-remediation table for S1
  comparison. That older artifact used single-batch capture, a symlinked
  catalog, no coverage and no overlap task; it stays supporting evidence only.
- **Cost is SDK-exposed pricing, never billing.** Subscription plans, provider
  credit or negotiated rates are invisible. The arithmetic tie to published
  rates is a consistency check, not a billing claim.
- **Single model, single run per task.** Run-to-run variance is unmeasured
  (one saved real run per task per tree; the smoke was repeated during review
  with a visibly different latency, but only saved runs are evidence). S1's
  before/after rerun confirms the problem rather than solving it: tasks 1–3
  load no agents-files, their deltas are exploration-path variance, and the one
  affected task moved against the expected direction. No delta from the rerun
  is attributed to deduplication. The corrected 2026-10-26 A/B added 4 paired
  repetitions of the one affected task with proven injection (A input-side
  3,123–3,199 on a byte-identical prompt), which is precisely the noise
  floor that hides the ~286-byte effect.
- **The earlier overlap real run used a small model and answered the marker
  wrong.** The definitive zai run answers it correctly. The audit is
  model-independent; the earlier usage numbers are valid for that model and
  call, but they are not the zai baseline. Single runs still mean answer
  quality is one observation per task, not a pass rate.
- **No `/feature` end-to-end run is included.** The baseline measures the
  child-call exploration pattern (the unit S1 changes). Verify-command
  durations are still NOT measured (`CommandResult` has no duration field), and
  the workflow-level `elapsedMs` on `workflow.outcome` measures the launch
  segment only.
- **Cache behavior is provider-specific.** zai reported cacheRead with zero
  cacheWrite on every call; the OpenRouter nemo model prices cacheRead at zero.
  Anthropic-style cacheWrite economics are not exercised.
- **Duplication is measured in bytes, not billed tokens — and (P1) the
  original audit never proved session delivery.** The audit proves the same
  canonical path entered the LOADER twice before S1 and once after; every
  pre-fix session received neither, because the runner passed an unreloaded
  loader. Since the P1 fix, the integration test and the corrected A/B's
  prompt gates prove delivery end-to-end (exactly 1 copy in B's real prompt,
  2 in A's). Even with delivery proven, the billed effect of those ~286
  rendered bytes (~70 tokens heuristic) was **not detected in the four
  corrected same-tree A/B pairs**. We chose not to expand the experiment;
  the sample does not establish a detection limit or rule out a small benefit.
- **The A/B result is bounded to one task, model and fixture.** It measures the
  only mechanically affected task (`context-overlap`, 220 duplicated bytes /
  286 rendered); tasks whose context duplication is larger could in principle
  behave differently, and no such task exists in the current protocol. Single
  model (`zai/glm-5.2`); n=4 pairs; latency shares one machine. The harness
  replicates the (fixed) `PiAgentRunner.run()` session construction —
  including the reload-before-session contract — rather than calling `run()`
  itself (the production runner exposes no loader override, by design), with
  the trade-off stated: A/B are internally perfectly comparable and gated on
  the actual prompt, but B did not literally execute the production `run()`
  method; the integration test covers that path offline.
- **Pre-fix protocol runs measured empty-prompt children.** Every
  `PiAgentRunner`-based run recorded in this report (2026-10-24/25 baseline,
  post-S1 rerun, first A/B) ran with zero injected context and zero skills.
  Their usage/cost/latency/quality numbers are valid for exactly those calls,
  but they say nothing about injection effects; injection exists only since
  the P1 fix, which is therefore a *behavior change* for every future
  `/feature` run, not merely an instrumentation fix.
- **The `onEvent` `args` whitelist is instrumentation only.** It exists so this
  protocol can count reads/rereads; it is not persisted and carries no file
  contents.
- **Runner internals are exercised by real calls, not a fake-model harness.**
  The `agent_end` fold is unit-tested on SDK-shaped messages; the smoke,
  overlap and pre-remediation runs exercised the real path. Nonzero retry
  summation is unit-tested only.
- **Timing shares the machine.** Absolute latencies are not reproducible to the
  millisecond across machines; the 7 ms wall-clock cross-check is local.
