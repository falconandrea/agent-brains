## Spec

1. **Full-profile failure can still partially mutate the installation (F1, partial).** `setup.sh` dispatches `link_opencode` before `prepare_full_agents`; the latter can fail when a curated `.agents` directory contains managed links plus foreign content. If `.opencode` was absent, `full` exits nonzero after creating it. F1 requires: “Resolve and validate the requested profile before deleting or replacing existing links,” and the acceptance criteria require blocked/invalid setup to leave the installation intact. Validate the conversion before any link operation (or roll back the link).

2. **Manifest includes are not fully validated (F1/T2, missing).** `resolve_manifest` constructs `"$PROFILES_DIR/$name.list"` from an unvalidated name and accepts any `@include` token. An entry such as `@include ../outside` can read a file outside `profiles/` and use its skill lines, so path traversal is accepted as a valid profile. F1 requires validating the requested profile before mutation; T2 specifically requires manifest validation “including `@include` cycles and invalid entries.” Restrict profile/include names to one safe segment and reject traversal.

3. **F5 test coverage misses unlinking foreign workflow links (partial).** `tests/setup-unlink.test.ts` verifies a foreign `.agents/workflows` symlink survives setup, but the unlink cases exercise foreign skill, whole-directory, and `.opencode` links only. The acceptance criterion explicitly requires: “Setup and unlink preserve foreign skill, workflow, and whole-directory links.” Add an unlink case for a foreign workflow symlink.
