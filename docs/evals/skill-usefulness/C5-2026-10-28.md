## Priority findings and disposition proposals

1. **Role/instruction conflict: `simplify`.** The router categorizes it as
   `review`, selecting it for reviewer and security-reviewer roles when present
   in the profile. Its body explicitly runs formatters, removes code and runs
   tests. `resolveTools` keeps read-only sessions on their read-only tool set;
   this is an instruction mismatch, not a demonstrated write escape. Propose
   keeping cleanup in the writer/main session and excluding mutation guidance
   from read-only review. Validate before changing routing.
2. **UI trigger overlap and interruption risk.** `designer` applies before any
   UI writing/review and asks whether to create a design system when absent.
   `ui-ux-pro-max` covers virtually all UI work, `frontend-design` adds visual
   direction, and Tailwind guidance covers common component styling. Next.js
   includes all these. Preserve project design-system authority; evaluate
   whether small edits need only `designer` plus stack guidance and broader
   design needs the optional database/aesthetic skills. The missing-system
   question is a potential unnecessary interruption where scope is already
   authorized, not evidence that the specialist resources have no value.
3. **Unavailable dependency.** `nodejs-backend-patterns` directs testing to
   `javascript-testing-patterns`, absent from the canonical store and profiles.
   Its own entry point is mostly general advice with detailed references.
   Propose replacing the unavailable dependency with existing test guidance;
   compare its detailed references against `nodejs-best-practices` before any
   merge. An externally installed skill might satisfy that name in a consumer;
   repository-managed distribution does not supply it.
4. **Overlapping interview entry points.** `grilling` asks a whole decision
   frontier per round; `grill-with-docs` intentionally uses one question at a
   time and gates document output. Both are common-profile skills. These are
   different interaction contracts, not interchangeable duplicates. Propose
   clearer trigger separation and preservation of explicit user preference;
   compare their decision coverage and interruption cost before consolidation.
5. **Execution and remote dependency surface.** `react-doctor` asks for an
   `@latest` CLI on React changes and a remotely fetched playbook for full
   triage; `shadcn` declares CLI tools and requires docs lookup. This can be
   useful current tooling, but needs distinct shell-capable and no-shell cases.
   Frontmatter tool declarations do not grant tools beyond harness policy.
   Inspect remote content only during a separately authorized execution case;
   no claims about its current contents are made here.
