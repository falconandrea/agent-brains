# U1 — UI guidance screening results

Date: 2026-10-28. Baseline: `27b9be7`. Bounded four-call trial complete;
C5 is now closed with limits in the [closure decision](C5-CLOSURE-2026-10-28.md).
This U1 trial made no skill, profile, runtime or consumer changes.

## Experiment

[Protocol fixed before calls](U1-PROTOCOL-2026-10-28.md). Reused the committed
fixture: change only gap-1 to gap-2 in an existing email-field component,
following its supplied design system. Four fresh `zai/glm-5.2` sessions,
thinking off, AB/BA order. Identical request, component, design system, system
prompt and no-tool environment. A is byte-identical to B plus only extra
guidance. Actual system/user prompt hashes are retained per call.

- B: designer + tailwindcss-development.
- A: B + frontend-design + ui-ux-pro-max + tailwind-design-system.

Only the UI entry-point guidance slice is compared, supplied in the user
prompt. No full framework profile, production skill loader, description-trigger
selection, reference database, remote content or browser rendering is tested.

All four HTML blocks are byte-identical after trimming outer whitespace and
match the expected one-token correction. The structural evaluator also confirms

attribute/class ordering and formatting whitespace. Manual inspection of all
four full answers found one concise explanatory sentence each, no clarification
or approval requests, no new artifact/redesign suggestions and no unobserved
test or rendering claims. All calls have one successful assistant batch; no
provider errors, aborted answers or retry batches were observed.

Input plus cache-read tokens are 16,689 for each A call and 1,860 for each B
call; output totals are 144 versus 193. These are observed provider usage fields,
not a general context threshold. Cache warmth is unequal: first A reports 384
cached tokens, second A 16,640; both B calls 1,856. The observed cost gap is
therefore not an isolated or generalizable savings estimate. Total reported
SDK cost for the four calls is $0.02978096, not independently verified billing.

## Decision and limits

The reduced guidance was sufficient for this narrow spacing task. No incremental
correctness, scope-control or interruption benefit was detected from the extra
three entry points; neither set caused observable harm. Two pairs on one easy
fixture do not establish equivalence or justify deleting/merging design skills.
The explicit task already prohibited redesign and unnecessary clarification, so
this cannot establish how the skills behave with a weaker brief. Database and
specialist reference value, rendered visual craft and missing-design-system
behavior remain unmeasured. Do not expand this saturated fixture.

Keep current production profiles. A useful next comparison is U3 (new UI with
real design choices) or a realistic scoped UI task with a less prescriptive
brief. Define its grading criteria and bound before new calls. Prefer using
specialist design guidance when the task actually requires design decisions;
this is a scoped recommendation, not a production routing change.
