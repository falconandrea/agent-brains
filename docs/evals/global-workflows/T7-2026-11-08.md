An independent review of the runner found four defects; all were fixed in the

2. The developer-ran and README-implemented checks passed vacuously whenever
   the outcome was not `completed`; both are now unconditional.
3. `SHA256SUMS` was computed before `result.json` was rewritten, so manifests
   could describe stale result bytes; `result.json` is now written first and
   the manifest always covers it. The synthetic packages' manifests were
   regenerated for coherence (artifact contents untouched); the live
   Cancel/resume packages were verified coherent.

   an explicit empty expectation, so any rendered select dialog fails fast
   instead of waiting out the timeout.

A second review round found three more defects, fixed the same way (code plus
`selfcheck` coverage; no new TUI run, verdicts unchanged):

5. A gate split across output blocks could match on its message before the
   navigation chrome arrived, and the following `expect=()` wait would then
   misread the pending footer bytes as an unexpected dialog. The gate
   predicate now requires the complete frame including the chrome, so the
   wait cannot return while frame bytes are still in flight; `selfcheck`
   reproduces the split-block case.
6. The prefix check split the log into lines and dropped blank ones,
   accepting newline/blank-line edits inside the supposedly frozen prefix.
   It now compares raw bytes: the finished log must `startswith` the frozen
   bytes exactly.
7. The artifact check only required each file to hash to *one of* the two
   approved hashes, so two PRD copies or swapped file names could pass. It is
   now path-bound: the `prd-*` file must hash to `prdSha` and the `tasks-*`
   file to `tasksSha`.

The corrected checks were re-verified offline against the preserved live
