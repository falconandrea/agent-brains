## Verification reliability

- [x] **T4 — Retain metadata under stack overrides (F3).** `resolveStack` now always detects metadata and applies the configured primary through the pure `applyStackOverride` helper (`src/stack.ts`): languages, package managers and secondary frameworks are repository facts and always retained; explicit `config.verify` stays authoritative (unchanged, pinned by tests). Capability decision: when the configured primary lives in the same ecosystem as the detected one (only `laravel` is PHP; every other profile is node-based) all capabilities are kept — an explicit `laravel` on a detected Laravel repo keeps pest/pint/phpstan; on a cross-ecosystem override only the configured ecosystem's capabilities survive (PHP set: pest/pint/phpstan), because the other ecosystem's tooling can never run in that profile's verification path; the detected winner framework token is dropped when the primary changes. TDD regressions (4 failed pre-fix): Laravel checks preserved, pnpm selection, cross-ecosystem filtering both directions (artisan fallback), `config.verify` precedence — unit + workflow level. Verified: targeted tests, `npm test` 253/253, `npm run typecheck`, `git diff --check`. The interactive low-confidence human choice still swaps the primary without the ecosystem filter (pre-existing behavior, F3 targets `config.stack`).
- [x] **T5 — Define verification timeout configuration (F4).** `verifyTimeoutMs` (ms) added to `PiBrainConfig` with default 600000 (10 min) and validated bounds 1000–3600000 (`src/config.ts`: `DEFAULT/MIN/MAX_VERIFY_TIMEOUT_MS`). A missing key silently keeps the default — the legacy-config case — while a present-but-invalid value (non-integer, out of range, wrong type) falls back with a warning naming the bounds. Documented default, bounds and platform behavior in `docs/pi-brain/README.md` ("Verification timeout"). TDD: 3 config tests failed pre-implementation (key absent), pass after.
- [x] **T6 — Enforce verification timeouts and cleanup (F4).** `ShellVerifyRunner` now spawns each command with `detached: true` so it leads its own process group; on timeout (or `/flow stop`) it SIGTERMs the group, escalates to SIGKILL after a grace period (default 5s), and destroys its pipe ends so a straggler cannot keep the promise pending. Plain `spawn` is required: the exec family silently drops `detached` on current Node (verified — the child keeps the parent's pgid). Results distinguish timeout (exit 124, `timedOut`, message naming command and limit), cancellation (exit 143, `cancelled`) and ordinary failures (real exit code); the workflow routes timeouts to the developer as timeout findings and returns `cancelled` when the abort lands mid-verify (retry budget untouched); runaway output (>16MiB) is truncated with the tree killed, preserving exec's old maxBuffer contract. Two-axis review found and fixed one real defect: the escalation timer must stay armed after the shell closes, or a grandchild that traps SIGTERM and holds no pipes survives (regression test verified by mutation). Lock release after timeout/cancellation is guaranteed by construction — the workflow now always returns an outcome and the extension releases the lock in its `finally` (Pi surface, not unit-testable; the workflow-return precondition is covered by tests). TDD: hanging command blocked 30s pre-fix and cancellation leaked the grandchild; covered now by 11 runner tests (fast success, ordinary failure, timeout, tree kill, SIGKILL escalation incl. off-pipe grandchild, cancellation, abort between commands, output overflow) plus 2 workflow tests. Second round (user-reproduced defects, both fixed red-first): (1) the result was resolved at shell close while the SIGKILL of surviving children was still scheduled — run() could return, and the workflow release the lock, with a live child (repro: 266ms return, child alive); `settle()` now waits for the process group to be empty before resolving, verified by the test at return time (no post-run polling), with a bounded give-up for unkillable D-state survivors and a last-resort resolution if 'close' never fires. (2) A late timeout could overwrite an ongoing cancellation (cancel 100ms, timeout 300ms, grace 500ms → exit 124); termination is now a single idempotent cause where the first one wins, and the abort path deactivates the concurrent timeout timer. Third round (final review round): `settle()` now returns the cleanup outcome and the result message is qualified when the group could not be confirmed dead within the bounded wait ("check for leftover processes" instead of "was terminated"), matching the README's qualified guarantee; `groupGone()` counts the group as absent only on ESRCH (EPERM keeps waiting). The unkillable D-state branch is not reproducible in an automated test and is documented as a verification limit. Depends on T5.
